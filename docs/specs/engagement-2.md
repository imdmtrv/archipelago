# Залипательность, шаг 2: распродажа вместо переезда, слухи с источником, понятные цели

Ветка `claude/engagement-2`. Продолжение [шага 1](engagement-1.md) по отзыву владельца после игры:

- **Повышение с переездом** непривлекательно — убираем. Вместо него **распродажа у соседа**: сосед в беде срочно
  продаёт свой актив за 60–75% цены. Урок: свободные деньги — это возможность купить хорошее дёшево.
- **Слухи сбываются всегда** — неинтересно. Теперь у слуха есть **источник**: надёжный (старые рыбаки, банк)
  сбывается примерно 9 раз из 10, рыночная болтовня — меньше чем в половине случаев. Бывают и ложные слухи.
  Урок: смотрите, откуда информация.
- **Окно «Цель выполнена»** не говорит, чего вы добились. У каждой цели теперь свой текст в прошедшем времени.

Общие правила — как в [шаге 1](engagement-1.md#общие-правила). Каждый исполнитель читает «Контракт» и свой раздел.

## 1. Движок — Codex (первым)

**Файлы:** `packages/engine/**`.

- **Убрать переезд** целиком: генерация, решение, представление, стратегия «Переезжает всегда» и её строка целей
  в симуляторе, тесты.
- **Распродажа у соседа** (`fireSale`). Сосед «в беде» — бот с займом у ростовщика или с наличными меньше
  `FIRE_SALE_TROUBLE_CASH` (сначала с ростовщиком, иначе с наименьшими наличными), у которого есть неповреждённый
  доходный актив (`kind: 'asset'`, не слот `finance`). Актив — случайный из таких; `price = round10(asset.price ×
  range(FIRE_SALE_DISCOUNT))`. Развилка доступна, если у игрока есть свободное место этого типа; если монет не хватает,
  она всё равно выпадает — с `canAccept: false` и `reason: notEnoughCash` (упущенная возможность — тоже урок о запасе).
  Принять: актив переходит игроку (свободный `slotIndex` в его слоте, `price` = заплаченная цена, `boughtWeek` = текущая
  неделя, уровень, доход и содержание — как были), сосед получает монеты. Нет места/монет/актива к моменту решения —
  соответствующая ошибка (`slotFull`, `notEnoughCash`, `noSuchAsset`), а пропавший актив снимает развилку.
  `choiceView` — поля варианта `fireSale` из `types.ts` (окупаемость и свобода — как у сделок с доски).
- **Слухи с источником.** Настоящее событие планируется как сейчас, его источник — надёжный с вероятностью
  `RUMOR_RELIABLE_SHARE`, иначе болтовня; `real: true`. Затем с шансом `FALSE_RUMOR_CHANCE` в неделю планируется
  ложный слух: вид — по `WORLD_EVENT_WEIGHTS`, срок и окно — как у настоящего, неделя должна быть свободна;
  источник — болтовня с вероятностью `FALSE_RUMOR_GOSSIP_SHARE`, иначе надёжный; `real: false`. В неделю ложного слуха
  вместо события — `rumorFalse`. На одну неделю — не больше одного слуха. `rumorViews` отдаёт `source`; точная неделя
  при знаниях 2 — как прежде, и для ложных слухов тоже (знания не отличают правду от лжи).
  Ожидаемо: надёжный сбывается ≈ 9/10, болтовня < 1/2 — проверь тестом на многих сидах.
- **Миграция** v5 → v6 (и всё старше): у `upcoming` — `real: true`, `source: 'reliable'`; развилка `promotion` снимается;
  поле `promotions` удаляется.
- **Симулятор**: разумный покупает на распродаже, если может, окупаемость ≤ 30 недель и после покупки остаётся ≥ 80;
  «Слушает слухи» верит только надёжным. Новая стратегия «Не покупает на распродажах» и цель: разумный не позже неё
  и раньше не больше чем на 4 недели (распродажи помогают, но не решают). Остальные цели — `OK`; если цели ботов
  сдвинутся из-за распродаж, сообщи числа.
- **Тесты**: распродажа (доступность, `canAccept`, переход актива и место, монеты соседу, ошибки), слухи (источник
  в событии и представлении, `rumorFalse`, доли сбывшихся по источнику), миграция v5 → v6; тесты переезда убрать.
- Проверка: `npm run -s typecheck`, `npm test -- --reporter=dot`, `npm run -s sim` (все `OK`).

## 2. Интерфейс — Codex (после движка)

**Файлы:** `apps/web/src/ui/ChoiceModal.tsx`, `apps/web/src/ui/DealsTab.tsx`, `apps/web/src/i18n/index.ts`,
`apps/web/src/styles.css` (новые правила в конце), при необходимости `apps/web/src/store.ts`. Словари не трогать.

- **Окно распродажи** вместо переезда: заголовок с именем соседа, текст (`asset` — винительный падеж, цена и обычная цена),
  строки «будет приносить …» и «окупится за …», «Свобода: X% → Y%», ссылка на карточку соседа, подсказка; кнопка
  «Купить за …» неактивна с текстом ошибки, если `canAccept: false`; тост `bought`.
- **Цель выполнена**: `goalDone.text(done, reward)`, где `done` — `ui.goals.items[id].done`.
- **Слух** в окне недели: `events.rumor[source][kind](когда)` (`source` по умолчанию `reliable` для старых отчётов);
  `rumorFalse` — `title` и `text(вид)`, где вид — `ui.rumors.kinds[kind]`.
- **Плашки слухов**: `chip(вид, когда, ui.rumors.source[source])`, подсказка — `sourceHint[source]` (и `exactHint`, если
  неделя точная). Болтовня — визуально тише надёжного (например, пунктирная рамка), тон по виду события как сейчас.
- Проверка: `npm run -s typecheck`, `npm run -s build 2>&1 | tail -5`.
